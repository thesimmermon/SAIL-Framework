The Problem

AI can read your code.
It shouldn't have to infer your architecture.

Source code tells an AI agent what exists today. It does not reliably tell the agent what should exist.

Where does one system end and another begin?
Which component owns this responsibility?
Which interfaces are architectural contracts?
Which dependencies are intentional?
Which performance, security, or compliance constraints must survive the next change?

Humans have struggled with the same ambiguity for decades. AI makes the consequences faster.

SAIL was designed to make architecture understandable. It turns out machines need that clarity too.

Shared Source Of Truth

One architecture. Two readers.

For People

Architecture they can understand.

SAIL gives executives, architects, developers, and other stakeholders views appropriate to the decisions they need to make.

Start with boundaries and context. Reveal structure, behavior, interfaces, and constraints as more detail becomes necessary.

For Machines

Architecture they don't have to guess.

The same architecture can be represented as structured data.

Systems, components, responsibilities, interactions, interfaces, constraints, and validation rules become explicit architectural context that tools can inspect.

The diagram is the human-readable view.
The model is the machine-readable architecture.

What SAIL Is

Make architecture explicit.

SAIL is a formal visual language for system-level software architecture. It replaces ambiguous boxes and lines with a small, consistent vocabulary whose elements have defined architectural meaning.

  • Boundaries
  • Responsibilities
  • Behavior
  • Interfaces
  • Constraints
  • Validation rules
01

Structure

What exists?

Systems, service units, datastores, boundaries, dependencies.

02

Behavior

What does it do?

Interactions, scenarios, processes, responsibilities.

03

Intrinsic

What must remain true?

Performance, security, reliability, scalability, risks, constraints.

+1

Interfaces

What are the contracts?

Operations, communication patterns, technologies, ownership.

SAIL models architecture through Structural Architecture, Behavioral Architecture, Intrinsic Architecture, and Interfaces (+1).

Human Continuity

The reader changed.
The requirement didn't.

Architecture has always succeeded or failed based on whether its reader could understand it.

An executive needs scope and dependencies. An architect needs boundaries and constraints. A developer needs responsibilities and contracts. An AI coding agent needs those same decisions expressed explicitly enough that it doesn't have to guess.

SAIL uses progressive disclosure so the same architecture can remain understandable across those levels.

"If a diagram needs an expert narrator to be understood, it's not documentation."
